# dsh-interview 重构需求基线

## 1. 产品定位

dsh-interview 是一个本地优先的 AI 面试训练工作区。它同时提供自然语言和可视化 UI 两种入口，并保证两种入口共享同一套业务用例、流程状态与持久化数据。

重构不保留旧版工具协议、JSON 数据结构和前端实现兼容性。

## 2. 核心用户流程

### R1 创建练习

- 只支持背八股、模拟面试、场景题三种模式。
- 第一步只询问模式；模式确定后再询问该模式缺少的配置，不提前询问其他模式的字段。
- 背八股只配置主题；场景题只配置主题。
- 模拟面试只配置简历、面试官风格、是否手撕代码和面试难度。
- 所有配置都必须来自用户明确输入，禁止 Agent 推断、补全、沿用历史值或采用默认值。
- 配置缺失时只询问当前模式的缺少项，不重复已明确项，不增加产品规格之外的问题。
- 创建后进入“等待出题”状态，并通知 Agent 生成第一题。

### R2 进行练习

- Agent 可以创建题目，用户可以在正常聊天输入框中回答。
- 每轮只生成一道简单扼要、只包含一个核心考点的问题；不得拼接多个子问题或附带答案、提示和作答清单。
- 当前题未完成点评讲解前禁止创建下一题，任意时刻最多只有一道当前待答题。
- 用户可以直接作答，也可以点击“看答案”跳过作答并生成本题讲解。
- 每次回答形成独立作答记录，不覆盖已评价的历史作答。
- 选择“重新作答”只改变当前焦点；先前全部作答、评价和时间信息必须保留，新回答必须新增一条作答记录。
- 点击“下一题”后自动请求 Agent 生成并展示下一题，不要求用户再次发送消息。
- 当前流程必须由显式状态机约束，禁止越过回答直接评价或在点评讲解完成前进入下一题。
- 支持打开历史题、重新作答、暂停后恢复和主动结束。

### R3 评价与讲解

- 评价包含 0–10 分总分、文字反馈和可选维度分。
- 评价完成后自动继续生成讲解，不向用户展示半成品评价卡片。
- 讲解必须详细解释当前知识点，目标是帮助用户真正理解，而不是只罗列结论。
- 讲解末尾必须包含可直接背诵和在面试中复述的非空“直接背”。
- 直接看答案时展示讲解和“直接背”，不伪造用户作答、评分或评价。
- 作答后的评分、评价、讲解和“直接背”统一展示为点评讲解，采用上下结构，不重复展示用户作答，不提供复制按钮。
- 评价、讲解和历次作答均结构化持久化。

### R4 结束与练习总结

- 点击“结束练习”后基于完整练习、题目、历次作答、评价和讲解生成练习总结。
- 总结必须持久化到练习，结束卡片和练习详情读取同一份权威数据。
- 练习完成后不得继续出题或作答；重新打开后才可继续。

### R5 练习与题目 CRUD

- 练习支持新增、列表/详情查询、按合法配置修改和删除。
- 题目支持新增、列表/详情查询、修改题干和删除；删除后题号连续重排。
- 修改操作必须通过领域校验，不允许绕过模式配置和工作流约束。
- 支持练习搜索、模式和状态筛选。
- 支持查看每题的历次作答、评价和讲解。
- 支持选择、重新打开和删除练习；删除必须经过 UI 确认或明确的 Agent 意图。
- 切换练习时，工具结果必须把练习配置、练习总结、全部题目、全部历次作答、评价和讲解作为结构化上下文返回给模型。
- 通过 UI 切换练习后必须立即唤醒模型加载上述上下文，并由模型只回复当前练习已经切换成功，不等待用户再次发送消息。

### R6 复盘与导出

- 提供练习级题数、已评价数、平均分和结论。
- 提供跨练习的主题掌握度、练习趋势和薄弱主题。
- 支持当前、指定和全部练习导出 Markdown。
- 导出文件通过受控下载接口访问，不暴露任意本地路径读取能力。

### R7 可视化 UI

- 聊天流展示题目、点评讲解、总结和导出结果卡片。
- 练习档案提供搜索、筛选、详情、继续、删除和导出操作。
- 练习详情提供练习编辑、题目编辑和题目删除操作。
- 右侧时间轴展示当前练习题目与状态。
- UI 只消费服务端读模型，不从工具入参重建业务数据。
- 所有 UI 命令与 Agent 工具调用进入同一应用层。
- UI 文案只描述真实状态和可执行动作，禁止硬编码提示、示例数据或无业务价值的装饰信息。

## 3. 架构约束

### A1 单一领域内核

- `Practice` 是聚合根，管理题目、作答、评价、讲解和生命周期。
- `Question` 不保存“最新回答/最新分数”等冗余投影。
- 会话游标与练习内容分离。

### A2 显式工作流

工作流阶段固定为：

```text
awaiting_question
→ awaiting_answer
├─ 用户作答 → awaiting_evaluation → generating_explanation ─┐
└─ 直接看答案 ─────────────→ generating_explanation ───────┤
                                                            ↓
                                                      awaiting_next
                                                            ↓
                                          generating_summary → completed
```

重新作答会从目标题进入 `awaiting_answer`，不会创建重复题目。

### A3 应用用例

- 写操作使用命令：开始/修改/删除练习、出题/修改/删除题目、提交回答、直接看答案、保存评价、完成复盘、下一题、重答、完成总结、恢复、选择和导出。
- 读操作使用查询：当前会话、练习列表、练习详情、题目详情和能力洞察。
- HTTP、DSH 工具和 UI 不直接读写数据库。

### A4 端口与适配器

- 领域层不依赖 DSH、HTTP、SQLite、文件系统和 React。
- 应用层只依赖 Repository、事件发布器、导出器、时钟和 ID 生成器端口。
- SQLite、Markdown 导出、DSH Tool、HTTP 和 React UI 都是可替换适配器。

### A5 工具协议

对 Agent 暴露一个动作一个工具的原子协议，禁止使用 `command` 联合承载多种参数形状。

- 每个工具通过 `required`、`minLength`、数值范围和 `additionalProperties: false` 硬性约束参数。
- `interview_present_question` 只保存并展示模型已经生成完成的非空题目，不承担题目生成。
- 回答、评价和复盘分别使用独立工具；评价后必须根据 `nextAction` 自动完成复盘。
- 完整讲解和“直接背”字段必须在 Schema 层设置为非空必填。
- 工具返回统一的交互状态、下一步动作、UI 展示资源、Assistant Text 契约和数据修订号。
- Client 根据结构化展示资源 ID 读取权威读模型，不解析工具文本或复制工具参数。
- Agent 协议错误标记为可恢复且不产生 UI，用户错误和系统错误进入独立可见通道。

### A6 持久化

- 使用 SQLite，表结构至少包含 practices、questions、attempts 和 session_cursors。
- 聚合保存必须处于事务中，并启用外键约束。
- 不实现旧 JSON 数据自动迁移。

## 4. 非功能要求

- 所有写命令必须进行参数校验和状态校验。
- 业务错误使用稳定错误码，不依赖中文消息判断类型。
- HTTP 请求体限制大小，所有响应禁止缓存。
- Markdown 内容默认按纯文本数据处理，由统一渲染组件展示。
- 每个需求批次独立提交、可单独回滚。
- 本地提交遵循 Conventional Commits，使用中文说明，不执行 push。

## 5. 验收标准

- 领域状态机、应用用例、SQLite Repository、HTTP、工具协议和 UI 均有自动化验证。
- 完整作答流程可执行：显式配置 → 创建练习 → 单题出题 → 回答 → 保存评价 → 自动完成复盘 → 重答/下一题 → 生成总结 → 查看档案 → 导出。
- 直接看答案流程可执行：单题出题 → 看答案 → 生成详细讲解和直接背 → 下一题/结束。
- 练习与题目的新增、查询、修改和删除均可从 Agent 工具和可视化 UI 完成。
- 切换练习后模型一次获得该练习的完整结构化上下文。
- 自然语言与 UI 操作产生一致的数据结果。
- 不再存在万能 `InterviewStore`、33 action 总分发器和 UI 字符串源码断言。
- `npm test`、语法检查、Client 构建和 `npm pack --dry-run` 全部通过。

## 6. 需求批次与提交计划

1. `docs: 明确重构需求与架构边界`
2. `feat(domain): 建立面试领域模型与工作流状态机`
3. `feat(application): 实现面试命令查询与端口`
4. `feat(storage): 使用 SQLite 持久化面试聚合`
5. `feat(adapter): 重写 DSH 工具与事件桥接`
6. `feat(ui): 重建面试训练与档案可视化界面`
7. `feat(report): 完善能力复盘与 Markdown 导出`
8. `test: 补全端到端验证与发布检查`
